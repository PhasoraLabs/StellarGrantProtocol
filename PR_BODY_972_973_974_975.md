## Changes Made

### `contracts/contracts/stellar-grants/src/errors.rs` — CI unblock (2 lines)
`ContractError::TooManyPublicReviews` is referenced by committed code
(`open_review.rs`) but the enum variant was dropped from `errors.rs` in an earlier
merge, so `cargo check --target wasm32v1-none` (a CI step) fails on `main` today.
Re-added as `TooManyPublicReviews = 147` (discriminant 146 is already taken by
`SwapNotImplemented`). No behavior change beyond making the workspace compile.

### `grant_timer.rs` — 12 tests (#972)
- `register` → `trigger` → `trigger` again: second call is a no-op (the `timer.fired` guard).
- Duplicate registration of an un-fired timer of the same `trigger_type` is rejected;
  a different type is still allowed; re-registration is allowed once the first has fired.
- Per-trigger-type eligibility gate exercised **both true and false** for all five types
  (`AutoExpire`, `AutoActivate`, `AutoCancel`, `AutoReleaseLockup`, `CustomCallback`).
- `AutoExpire` / `AutoCancel` route through `execute_timer_action` and land the grant in
  `Cancelled` with the expected `reason` string.
- `fires_at` time gate: nothing fires before the deadline, everything past it does; `pending_timers` reflects it.
- `cancel_timer` lifecycle: unauthorized caller rejected, owner cancels, second cancel → `TimerNotFound`.
- `register`/`trigger` on a missing grant; owner-or-admin-only registration.

### `badge.rs` — 7 tests (#973)
- Award through `try_award` — the exact hook the milestone-approval payout path calls
  (`lib.rs:723`) — with a contributor profile that meets criteria; `has_badge` / `get_badges`
  / `award_count` all reflect it.
- A `one_time` badge is **not** re-awarded on a second qualifying milestone on a different grant.
- Criteria-not-met and unregistered-contributor both deny the award.
- Reputation-threshold gate (`BronzeContributor`) checked at 99 vs 100.
- `get_criteria` mapping; `manual_award` is admin-gated.

### `reputation_decay.rs` — 9 tests (#974)
- `exponential_decay` at shifts exactly **31 / 32 / 33** — the `shifts >= 32` shift-overflow guard.
- `exponential_decay` floor clamp after shifting to 0; zero half-life / zero-inactivity passthrough.
- `linear_decay` driven below `config.decay_floor` clamps to the floor.
- `apply_decay`: `enabled = false` passthrough, below-`inactivity_threshold_ledgers` passthrough,
  and correct routing to `None` / `Linear` / `Exponential`.
- `days_inactive` / `ledgers_inactive` return 0 when `now <= last_action_at`.
- `effective_score` reads profile fields; `record_activity` updates `last_action_at` and
  is a no-op for an unknown contributor.

### `milestone_template.rs` — 6 tests (#975)
- `save_template` → `create_from_templates` round-trip produces the expected
  `(description, amount)` pairs and bumps `use_count`.
- `delete_template` by a non-owner is rejected; a deleted template can no longer be used
  by `create_from_templates`; a used template (`use_count > 0`) cannot be deleted.
- Private template usable only by its owner; `public_templates` / `templates_by_owner`
  filter visibility correctly.

### Note on `cargo test`

The CI contracts job runs `fmt` + `clippy --lib` + `check` (all wasm) and does **not**
run `cargo test`. The 34 new tests were verified by running them in isolation. A full
`cargo test` still fails to *compile* on this branch due to ~10 **pre-existing** broken
test modules on `main` (`lockup.rs`, `compliance.rs`, `merkle.rs`, `referral.rs`,
`milestone_extension.rs`, … — stale `Ledger` testutils API, `Grant::default()` misuse,
a use-after-move, etc.). Those are untouched here and are already fixed in the open
`#685 / #686` branch; this PR does not depend on them for CI to pass.
